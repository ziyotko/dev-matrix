## 文档说明

本计划依据《DSH 软件工程智能协同平台建设规划方案》制定，是平台建设落地的具体执行指引。整体遵循**自底向上、分层建设、底座先行、业务后行**的原则，共划分为 6 个建设阶段，明确各阶段核心目标、执行步骤、交付物与验收标准，可直接用于指导项目组按序推进建设工作，确保平台按标准、按节点高质量交付。

## 阶段一：底层引擎与多项目隔离体系建设

**周期**：第 1\-2 周
**核心目标**：搭建 DSH 底层运行底座，落地三级配置隔离体系与标准目录结构，实现 CLI 层面的多项目独立运行与互不干扰。

### 步骤 1：基础环境部署与标准目录初始化

- **执行动作**：

    1. 部署 DSH Headless 运行时与 Node\.js 基础环境，验证 CLI 基础可用性

    2. 按照方案标准创建`dsh-root`根目录，完整初始化以下目录：

        - `profiles/`（领域通用配置）

        - `patches/`（全局基线补丁）

        - `common_specs/`（全局开发规范库，含 backend/frontend/database/cross 子目录）

        - `common_skill/`（全局 Skill 池，含\_template 模板目录）

        - `dsh-platform/`（平台专属资产）

        - `projects/`（项目隔离根目录）

        - `.verify_cache.d/`（校验缓存目录）

    3. 设置目录权限：全局目录只读开放，项目目录按项目隔离权限

- **交付物**：标准化目录结构、DSH 运行环境验证报告

- **验收标准**：执行`dsh --version`正常返回；所有目录结构完整，权限配置正确

### 步骤 2：全局基线配置落地

- **执行动作**：

    1. 编写并放入`global-subagent.patch.yml`：统一全局子代理能力基线

    2. 编写并放入`verify-minimal.patch.yml`：全局最小权限基线

    3. 配置全局基础运行参数、模型服务端点、全局知识资产挂载路径

- **交付物**：2 个全局基线补丁文件、全局基础配置清单

- **验收标准**：加载基线配置后，七大领域智能体均可正常启动，权限约束生效

### 步骤 3：七大领域通用配置落地

- **执行动作**：

    1. 按领域分别编写`dispatch.profile.yml`\~`operation.profile.yml`共 7 个领域配置

    2. 每个配置包含：领域标准 Prompt 模板、模型参数、标准权限、领域知识资产挂载

    3. 统一放入`profiles/`目录

- **交付物**：7 个领域标准 Profile 配置文件

- **验收标准**：可通过`dsh --profile <领域>`单独调用对应领域智能体，输出符合领域规范

### 步骤 4：全局知识资产入库

- **执行动作**：

    1. 将《DSH 软件工程统一研发规范》按技术栈拆分，对应放入`common_specs/`各子目录

    2. 将已落地的 SQL 合规审核等 Skill 按标准结构放入`common_skill/`目录

    3. 初始化`dsh-platform/`平台专属规范与基础能力资产

- **交付物**：结构化的全局规范库、全局 Skill 池

- **验收标准**：智能体可通过 RAG 检索到对应规范与 Skill 内容

### 步骤 5：多项目版校验工具适配

- **执行动作**：

    1. 升级`verify_env.sh`脚本，新增`--project <项目ID>`参数

    2. 适配新目录结构，实现 0\-4 级分层校验、全项目批量校验、单项目专项校验

    3. 实现按项目配置哈希缓存校验结果，配置变更自动失效

- **交付物**：多项目版`verify_env.sh`校验脚本

- **验收标准**：执行`verify_env.sh --project test-project`可单独校验指定项目，校验结果准确

### 步骤 6：多项目隔离机制验证

- **执行动作**：

    1. 在`projects/`下创建`test-a`、`test-b`两个测试项目，初始化各自的 patches、specs、skills、output 目录

    2. 分别配置不同的智能体参数、专属规范与权限

    3. 同时调用两个项目的智能体执行任务，修改 A 项目配置，验证 B 项目不受影响

- **交付物**：测试项目目录、多项目隔离验证报告

- **验收标准**：项目间配置、数据、执行完全隔离，互不干扰；单项目停用不影响全局

## 阶段二：能力适配层核心服务开发

**周期**：第 3\-5 周
**核心目标**：开发中间件服务层，屏蔽底层细节，向上提供标准化 API，实现项目级调用管控、配置管理、校验执行与结果解析。

### 步骤 1：适配层工程骨架搭建

- **执行动作**：

    1. 基于 Go 语言搭建微服务工程，采用标准分层架构

    2. 初始化 MySQL 数据库，按项目 ID 分库分表设计核心业务表

    3. 搭建 API 网关框架，统一接口规范与错误码体系

- **交付物**：适配层工程骨架、数据库表结构设计

- **验收标准**：服务可正常启动，基础接口通断正常

### 步骤 2：配置管理服务开发

- **执行动作**：

    1. 实现全局、领域、项目三级 YAML 配置的读写、版本快照、对比、回滚

    2. 对接 Git 仓库，全局配置存主干，项目配置存独立分支

    3. 实现配置变更自动触发校验、灰度发布、全量发布能力

    4. 按项目路径隔离读写权限，跨项目无访问权限

- **交付物**：配置管理服务 \+ REST 接口

- **验收标准**：可通过接口修改项目配置，自动生成 YAML 文件，版本可追溯，校验触发正常

### 步骤 3：任务调度服务开发

- **执行动作**：

    1. 实现按项目独立任务队列，支持优先级调度、并发控制、超时管理

    2. 实现项目级进程池管理，绑定并发配额，通过 cgroup 设置 CPU、内存硬上限

    3. 实现三级配置自动拼接、DSH CLI 命令组装、参数数组式执行

    4. 落地白名单校验、特殊字符转义双重命令注入防护

    5. 实现任务状态实时同步、心跳检测、异常进程自动回收

- **交付物**：任务调度服务 \+ REST 接口

- **验收标准**：

    - 按项目隔离提交任务，队列互不抢占

    - 资源硬限制生效，单项目资源耗尽不溢出

    - 命令注入测试用例全部拦截成功

### 步骤 4：校验执行服务开发

- **执行动作**：

    1. 封装`verify_env.sh`脚本调用，支持全量校验、单项目校验、单领域校验

    2. 解析校验结果，输出结构化的阶段结果、失败详情、总耗时

    3. 实现按项目维度缓存校验结果，配置变更自动失效

- **交付物**：校验执行服务 \+ REST 接口

- **验收标准**：可通过接口触发校验，返回结构化结果，缓存机制正常

### 步骤 5：结果解析服务开发

- **执行动作**：

    1. 实现智能体非结构化输出的结构化解析，按标准模板提取核心字段

    2. 落地多级兜底解析机制：标准解析→宽松解析→原始文本归档

    3. 实现交付物自动归档至对应项目`output/`目录，按任务关联

    4. 实现大文件分片存储、断点续传、MD5 校验、定期清理策略

- **交付物**：结果解析服务

- **验收标准**：标准输出解析准确率≥95%；异常输出不中断流程；交付物自动归档路径正确

### 步骤 6：知识库同步服务开发

- **执行动作**：

    1. 实现三级知识库映射：全局→领域→项目

    2. 基于版本号与内容哈希实现增量差分同步，仅同步变更内容

    3. 实现向量索引增量更新，同步失败自动回滚

    4. 平台端发布的规范、Skill，10 秒内同步到底层对应目录

- **交付物**：知识库同步服务

- **验收标准**：平台修改规范后，底层目录自动更新；智能体可检索到最新内容

### 步骤 7：API 网关与统一鉴权

- **执行动作**：

    1. 所有接口强制校验`project_id`参数与对应权限

    2. 实现按项目维度限流、配额管控

    3. 统一调用日志，按项目记录，支持审计追溯

- **交付物**：API 网关服务

- **验收标准**：无`project_id`或越权调用直接返回 403；限流策略生效

## 阶段三：统一管理后台开发

**周期**：第 6\-7 周
**核心目标**：实现全局可视化管控，替代手工操作底层 YAML 与 CLI 的运维模式。

### 步骤 1：管理后台前端框架搭建

- **执行动作**：

    1. 基于 Vue 3 \+ TypeScript \+ Element Plus 搭建后台前端工程

    2. 实现统一认证、角色菜单权限控制、布局框架

    3. 对接后端 API 网关，统一请求拦截与错误处理

- **交付物**：管理后台前端工程骨架

- **验收标准**：不同角色登录显示对应菜单，接口调用正常

### 步骤 2：机构人员与权限管理模块

- **执行动作**：

    1. 组织架构管理：多级部门增删改查、层级调整

    2. 用户账号管理：账号创建、禁用、SSO 对接

    3. 角色绑定管理：全局角色 \+ 项目角色分配，支持一人多项目多角色

    4. 操作审计日志：全量记录所有操作，支持按项目、人员检索

- **交付物**：机构人员管理模块

- **验收标准**：可可视化维护组织与用户，权限配置后实时生效，操作全程留痕

### 步骤 3：项目全生命周期管理模块

- **执行动作**：

    1. 项目创建：输入项目信息后自动生成项目 ID、底层目录结构、初始配置模板

    2. 项目配置：基础参数、资源配额、模型权限配置

    3. 项目启停 / 归档：启用 / 停用项目，停用后释放资源、禁止调用

- **交付物**：项目管理模块

- **验收标准**：界面点击创建项目，底层自动生成完整目录与初始配置；停用后无法调用

### 步骤 4：智能体配置管理模块

- **执行动作**：

    1. 可视化编辑全局、领域、项目三级配置参数

    2. 补丁管理：启用 / 禁用、版本对比、一键回滚

    3. 配置变更后自动触发校验，校验通过方可发布

    4. 配置版本全记录，支持按项目对比

- **交付物**：智能体配置管理模块

- **验收标准**：界面修改配置→校验→发布全流程打通，最终同步到底层 YAML 文件

### 步骤 5：系统运维监控模块

- **执行动作**：

    1. 项目级运行监控：调用量、成功率、耗时、失败率统计

    2. 模型资源监控：按项目统计 Token 消耗、调用成本

    3. 环境状态监控：配置健康度、资产完整性监控，异常自动告警

- **交付物**：系统监控看板

- **验收标准**：可实时查看各项目运行状态，异常触发告警

## 阶段四：项目管理核心功能开发

**周期**：第 8\-10 周
**核心目标**：打通需求→任务→智能体执行→交付归档全链路，实现研发人员日常工作线上化。

### 步骤 1：项目空间前端框架

- **执行动作**：

    1. 实现项目切换器，用户仅可见有权限的项目

    2. 项目首页：基本信息、进度、里程碑、团队成员展示

    3. 项目内菜单按角色权限展示

- **交付物**：项目空间前端框架

- **验收标准**：跨项目数据完全隔离，用户仅能操作所属项目

### 步骤 2：需求与智能任务拆解

- **执行动作**：

    1. 需求录入：支持手动录入、批量导入、粘贴文档

    2. 一键智能拆解：调用 dispatch 领域智能体，自动生成子任务清单

    3. 任务管理：人工调整优先级、依赖关系、负责人，状态实时同步

- **交付物**：需求与任务管理模块

- **验收标准**：录入需求后点击拆解，自动生成结构化任务，匹配对应领域与阶段

### 步骤 3：执行协同工作台

- **执行动作**：

    1. 个人待办：聚合所有项目待办任务，按优先级排序

    2. 任务执行：智能体任务点击执行，实时展示执行日志与进度

    3. 结果审核：人工验收执行结果，支持通过、驳回重跑

    4. 协作评论：任务下评论、@提及、附件上传，仅项目内可见

- **交付物**：执行工作台模块

- **验收标准**：可在线完成任务执行→结果审核全流程，状态实时同步

### 步骤 4：交付物管理

- **执行动作**：

    1. 自动归档：智能体输出自动归档至对应项目目录

    2. 交付物目录：按项目、阶段、任务层级管理，支持在线预览、下载

    3. 版本对比、存储配额管理、超期自动清理

- **交付物**：交付物管理模块

- **验收标准**：任务完成后交付物自动归档，路径正确，可在线预览

### 步骤 5：基础项目看板

- **执行动作**：

    1. 项目进度甘特图、里程碑达成率

    2. 任务完成情况、团队负载统计

    3. 质量与风险概览

- **交付物**：项目级基础看板

- **验收标准**：项目经理可查看项目整体进度与数据，数据准确

## 阶段六：集成测试、试点验证与上线

**周期**：第 13\-14 周
**核心目标**：全链路验证，试点跑通，正式上线交付。

### 步骤 1：全链路集成测试

- **执行动作**：

    1. 端到端流程测试：配置→调用→执行→解析→归档全链路

    2. 多项目并行压力测试：5 个项目同时调用，验证隔离性与稳定性

    3. 异常场景测试：配置错误、输入异常、进程卡死、超时等

- **交付物**：集成测试报告、问题修复记录

- **验收标准**：核心流程通过率 100%；多项目并行稳定；异常场景有兜底

### 步骤 2：安全与性能测试

- **执行动作**：

    1. 安全测试：越权访问、命令注入、SQL 注入、XSS、敏感信息泄露

    2. 性能测试：接口响应、任务并发、大文件传输、知识库同步性能

- **交付物**：安全测试报告、性能测试报告

- **验收标准**：无高危安全漏洞；性能指标满足方案要求

### 步骤 3：试点项目接入验证

- **执行动作**：

    1. 选取 1\-2 个真实业务试点项目，完整录入项目、人员、配置、规范

    2. 跑通从需求到交付的完整研发流程
