## 文档说明

本手册是DSH软件工程智能协同平台的**全局Skill能力总册**，对应底层`common_skill/`全局公共Skill池，是全机构共享的智能体能力资产的官方说明与使用标准。
本手册明确了智能体Skill的定义、体系架构、能力清单、使用方法、管理规则与开发规范，是各项目调用Skill能力、运营团队管理Skill资产、研发团队自定义开发Skill的统一依据。本手册向下兼容领域级、项目级Skill，各级Skill均需遵循本手册设定的基础规范。

## 第一部分 总则

### 1\.1 编制目的

为规范DSH智能体Skill资产的管理、使用与开发，统一能力标准、沉淀复用资产、释放智能体生产效能，构建“全局共享\-领域专项\-项目定制”三级Skill能力体系，支撑研发全流程智能化落地，特制定本手册。

### 1\.2 适用范围

本手册适用于全机构所有基于DSH软件工程智能协同平台开展的智能体应用场景，覆盖Skill调用、管理、评审、开发全生命周期，适用于所有研发人员、质量管理人员、项目管理人员及平台运营人员。

### 1\.3 核心定义

**智能体Skill**：DSH智能体可加载调用的标准化能力单元，由YAML配置文件、Prompt模板集、执行逻辑脚本、知识附件与使用说明构成，是智能体能力扩展、场景复用、资产沉淀的核心载体。Skill可被七大领域智能体按需加载，实现特定场景下的专业化执行，替代重复人工工作。

### 1\.4 Skill 层级体系

与DSH三级配置体系对齐，Skill资产自上而下分为三级，优先级逐级提升，高层级覆盖低能力：

1. **全局通用Skill**（本手册核心内容）：全机构共享的基础能力，对应`common_skill/`目录，所有项目均可调用，是智能体的基线能力

2. **领域专用Skill**：面向七大研发领域的专项能力，对应领域通用配置，在全局Skill基础上进行领域深度强化

3. **项目专属Skill**：单项目定制化能力，对应`projects/{id}/skills/`目录，仅项目内可用，满足项目个性化场景需求

### 1\.5 与 DSH 智能体体系的对应关系

- DSH七大领域智能体（dispatch/requirement/development/quality/test/deployment/operation）为执行载体，Skill为可插拔的能力单元

- 智能体启动时按三级配置体系叠加加载对应Skill，项目专属Skill优先级最高，可覆盖全局Skill的默认参数

- Skill的启用、禁用、参数调整均通过配置补丁实现，不修改底层智能体核心逻辑

## 第二部分 Skill 体系架构

### 2\.1 Skill 标准组成结构

每个标准Skill必须包含以下核心文件，目录结构遵循统一规范：

```Plaintext
skill-name/
├── skill.yml            # 主配置文件，定义Skill元数据、参数、入口
├── prompt/              # Prompt模板集，按场景拆分
│   ├── system.md
│   ├── user.md
│   └── ...
├── script/              # 执行脚本与工具（可选）
├── assets/              # 知识附件与参考资料（可选）
└── README.md            # 使用说明文档
```

1. **skill\.yml**：Skill的核心配置，包含名称、版本、所属领域、输入参数、输出格式、权限要求、依赖项等元数据

2. **Prompt模板集**：智能体执行的提示词框架，定义任务目标、执行规则、输出标准，是Skill能力的核心载体

3. **执行脚本**：复杂场景下的辅助执行逻辑，支持Shell、Python等脚本，完成文件处理、系统调用等操作

4. **知识附件**：Skill专属的领域知识、规范文档、参考案例，支撑RAG检索增强

5. **说明文档**：包含功能说明、适用场景、调用示例、注意事项，供使用人员查阅

### 2\.2 Skill 分类维度

#### 2\.2\.1 按研发领域分类

- 调度类：对应Dispatch领域，负责任务拆解、优先级分配、资源调度

- 需求类：对应Requirement领域，负责需求分析、文档生成、需求校验

- 开发类：对应Development领域，负责代码生成、重构、注释生成

- 质量类：对应Quality领域，负责代码评审、合规校验、缺陷分析

- 测试类：对应Test领域，负责用例生成、测试执行、缺陷定位

- 部署类：对应Deployment领域，负责配置生成、环境部署、发布校验

- 运维类：对应Operation领域，负责故障分析、脚本生成、运维巡检

#### 2\.2\.2 按能力类型分类

- **生成类**：输出代码、文档、配置等结构化产物

- **审核类**：对输入内容进行合规性、规范性校验，输出问题清单

- **分析类**：对数据、日志、缺陷进行分析，输出结论与建议

- **执行类**：调用系统能力执行具体操作，输出执行结果

- **辅助类**：提供格式转换、信息提取、知识检索等支撑能力

### 2\.3 加载与生效机制

1. **三级叠加加载**：智能体调用时，按“全局Skill → 领域Skill → 项目Skill”顺序加载，同名称Skill后加载覆盖先加载的配置与参数

2. **按需挂载**：非全局默认Skill通过配置补丁显式声明启用，未声明的Skill不加载，避免资源占用

3. **增量生效**：Skill更新发布后，仅增量更新配置与资产文件，新调用任务自动加载最新版本，运行中任务不受影响

4. **版本锁定**：项目可通过配置锁定Skill版本，避免版本升级影响项目稳定性

### 2\.4 版本管理体系

1. **版本号规则**：采用语义化版本号`主版本号.次版本号.修订号`，主版本号代表能力架构变更，次版本号代表功能新增，修订号代表问题修复

2. **兼容性保障**：高次版本兼容低版本调用参数，主版本升级保留至少一个版本的过渡期

3. **下线流程**：废弃Skill提前公示，设置缓冲期，缓冲期内保留调用能力并提示迁移，到期后正式下线

## 第三部分 全局通用Skill能力清单

本部分为`common_skill/`目录下的全局共享Skill，所有项目默认可用，按研发领域分类。

### 3\.1 需求与调度领域

#### 3\.1\.1 需求结构化拆解Skill

- **功能说明**：将自然语言描述的业务需求，自动拆解为标准化的子任务清单，匹配对应研发领域

- **适用场景**：项目需求录入后智能任务拆分、迭代需求快速分解

- **输入要求**：完整的需求描述文档或文本，包含业务目标与验收标准

- **输出成果**：结构化任务列表，包含任务名称、所属领域、优先级、依赖关系、预估工时

- **调用方式**：项目管理界面一键调用 / Dispatch智能体自动触发

#### 3\.1\.2 任务优先级分配Skill

- **功能说明**：基于业务价值、紧急程度、依赖关系，智能评估并分配任务优先级

- **适用场景**：多任务并行时的优先级排序、迭代排期辅助

- **输入要求**：任务清单、业务影响范围、时间要求

- **输出成果**：带P0\-P3优先级标记的任务列表，排序建议与排期说明

- **调用方式**：任务管理界面批量调用

#### 3\.1\.3 需求文档标准化生成Skill

- **功能说明**：依据需求输入，自动生成符合《DSH软件工程统一研发规范》的需求规格说明书

- **适用场景**：初步需求转正式需求文档、需求文档初稿生成

- **输入要求**：需求要点、业务流程描述、核心功能点

- **输出成果**：标准格式的需求规格说明书（Markdown格式）

- **调用方式**：需求管理界面调用

### 3\.2 开发领域

#### 3\.2\.1 全栈代码生成Skill（规划中）

- **功能说明**：基于需求描述，生成符合技术栈规范的Go后端、Vue前端、MySQL数据库代码

- **适用场景**：通用业务功能快速开发、基础CRUD代码生成

- **输入要求**：功能需求描述、数据结构定义、接口定义

- **输出成果**：可运行的工程代码、接口文档、单元测试用例

- **调用方式**：开发任务界面调用

#### 3\.2\.2 接口文档自动生成Skill（规划中）

- **功能说明**：基于后端代码注释与接口定义，自动生成标准RESTful接口文档

- **适用场景**：接口文档同步更新、交付文档生成

- **输入要求**：接口代码文件或代码片段

- **输出成果**：标准接口文档，包含请求参数、响应结构、错误码、示例

- **调用方式**：代码提交后流水线自动触发 / 手动调用

#### 3\.2\.3 代码重构优化Skill

- **功能说明**：针对存量代码进行结构优化、规范对齐、性能优化，不改变业务逻辑

- **适用场景**：代码规范整改、遗留代码优化、技术债务清理

- **输入要求**：待重构代码、重构目标说明

- **输出成果**：重构后代码、变更说明、优化点清单

- **调用方式**：代码编辑器插件调用 / 任务界面上传代码调用

### 3\.3 质量与测试领域

#### 3\.3\.1 SQL合规审核Skill（已落地实现）

- **功能说明**：自动校验SQL语句的规范性、安全性与性能，识别语法问题、安全风险、慢查询隐患

- **适用场景**：代码提交前SQL校验、数据库变更审核、SQL上线前检查

- **输入要求**：SQL语句、数据库表结构

- **输出成果**：问题清单，包含缺陷位置、问题描述、严重等级、修复建议

- **调用方式**：流水线自动触发 / 质量评审界面调用

#### 3\.3\.2 代码静态评审Skill

- **功能说明**：依据统一研发规范，自动扫描代码问题，覆盖编码规范、安全漏洞、性能隐患

- **适用场景**：代码提交预审、合并前质量检查

- **输入要求**：代码文件、指定检查规则

- **输出成果**：缺陷报告，分级分类列出问题与修复建议

- **调用方式**：CI流水线自动执行 / 手动触发

#### 3\.3\.3 测试用例自动生成Skill

- **功能说明**：基于需求文档与代码逻辑，自动生成单元测试、接口测试用例

- **适用场景**：测试用例初稿生成、回归测试用例补充

- **输入要求**：需求文档、接口定义、代码文件

- **输出成果**：标准测试用例集，包含用例场景、前置条件、操作步骤、预期结果

- **调用方式**：测试任务界面调用

#### 3\.3\.4 缺陷根因分析Skill

- **功能说明**：基于缺陷描述与代码上下文，定位缺陷根因，给出修复建议

- **适用场景**：缺陷分析辅助、疑难问题排查

- **输入要求**：缺陷描述、错误日志、相关代码片段

- **输出成果**：根因分析报告、修复建议、影响范围评估

- **调用方式**：缺陷管理界面调用

### 3\.4 部署与运维领域

#### 3\.4\.1 部署配置生成Skill

- **功能说明**：基于项目信息与环境要求，自动生成标准化部署配置文件

- **适用场景**：新环境部署、配置文件生成、环境迁移

- **输入要求**：项目基本信息、环境参数、资源配置

- **输出成果**：部署YAML配置文件、启动脚本、环境说明

- **调用方式**：部署任务界面调用

#### 3\.4\.2 故障根因分析Skill

- **功能说明**：基于系统日志、监控指标与错误信息，智能定位运维故障根因

- **适用场景**：线上故障排查、异常告警分析

- **输入要求**：错误日志、监控数据、故障现象描述

- **输出成果**：故障根因报告、处理建议、恢复步骤

- **调用方式**：运维工作台调用

#### 3\.4\.3 运维脚本生成Skill

- **功能说明**：根据运维操作需求，生成标准化、可执行的运维脚本

- **适用场景**：日常运维操作、批量处理、巡检脚本开发

- **输入要求**：操作目标、执行步骤、环境信息

- **输出成果**：可执行Shell脚本、操作说明、风险提示

- **调用方式**：运维任务界面调用

### 3\.5 跨领域通用Skill

#### 3\.5\.1 文档格式转换Skill

- **功能说明**：实现Markdown、Word、PDF、HTML等研发文档格式的标准化转换

- **适用场景**：交付文档格式转换、文档归档标准化

- **输入要求**：源文档、目标格式

- **输出成果**：目标格式文档，保留原有结构与格式

- **调用方式**：文档管理界面调用

#### 3\.5\.2 代码注释生成Skill

- **功能说明**：为代码自动补充符合规范的功能注释、参数注释、返回说明

- **适用场景**：遗留代码补注释、代码规范整改

- **输入要求**：代码文件、注释粒度要求

- **输出成果**：补充注释后的代码

- **调用方式**：代码编辑器插件调用

#### 3\.5\.3 技术方案评审Skill

- **功能说明**：依据统一研发规范，评审技术方案的完整性、合理性、合规性

- **适用场景**：技术方案预审、架构设计评审

- **输入要求**：技术方案文档

- **输出成果**：评审意见清单，包含问题点、优化建议、风险提示

- **调用方式**：方案评审界面调用

## 第四部分 Skill 使用操作指南

### 4\.1 平台端可视化使用

#### 4\.1\.1 调用入口

- 项目空间内各业务场景（需求、开发、测试、部署、运维）均内置对应Skill快捷调用入口

- 全局Skill库页面可查看所有可用Skill详情，支持按领域、类型筛选检索

- 个人工作台可收藏常用Skill，快速发起调用

#### 4\.1\.2 操作流程

1. 选择对应Skill，进入调用页面

2. 填写输入参数，上传必要的附件文件

3. 确认执行配置（可自定义高级参数，默认使用全局配置）

4. 提交执行，实时查看执行进度与日志

5. 执行完成后查看结果，下载交付物，支持驳回重跑

6. 对Skill执行效果进行评分与反馈

#### 4\.1\.3 结果与交付物管理

- 所有执行结果自动归档至对应项目的交付物目录，按任务关联

- 支持在线预览结果、下载源文件、历史版本对比

- 执行记录永久留存，支持按项目、时间、Skill类型检索追溯

### 4\.2 配置化调用方式

#### 4\.2\.1 YAML配置绑定

- 在领域Profile或项目Patch配置中，通过`skills`字段声明启用的Skill与参数

- 示例：

```YAML
skills:
  - name: sql-audit
    version: 1.2.0
    params:
      severity_level: warning
      auto_block: true
```

- 配置生效后，对应领域智能体执行任务时自动加载该Skill

#### 4\.2\.2 CLI命令行调用

- 底层可通过DSH CLI附加参数调用指定Skill

- 调用格式：`dsh --profile headless --skill <skill-name> --skill-param key=value "任务指令"`

- 仅开放给管理员与运维人员用于调试与批量操作

### 4\.3 权限与约束

#### 4\.3\.1 权限映射

|角色|调用权限|管理权限|
|---|---|---|
|系统管理员|全部Skill调用权限|全局Skill管理、版本发布|
|项目经理|项目内所有可用Skill调用权限|项目专属Skill管理|
|开发工程师|开发、质量类Skill调用权限|无|
|测试工程师|测试、质量类Skill调用权限|无|
|运维工程师|部署、运维类Skill调用权限|无|
|普通成员|仅查看Skill说明，无调用权限|无|

#### 4\.3\.2 使用约束

- 按项目分配调用频次与资源配额，超出配额任务进入等待队列

- 禁止使用Skill执行未经授权的生产环境操作、敏感数据访问

- 核心业务场景的Skill输出必须经过人工审核确认，方可正式生效

- 禁止利用Skill生成违反法律法规、安全规范的内容

### 4\.4 效果评价与反馈

1. 每次Skill执行完成后，支持使用人员对执行效果进行1\-5星评分，提交问题与优化建议

2. 平台定期收集反馈，同步给Skill维护团队，持续迭代优化

3. 高评分、高复用的Skill纳入优质资产推广，低评分Skill启动优化或下线评估

## 第五部分 Skill 管理与运营

### 5\.1 Skill 入库评审机制

#### 5\.1\.1 入库标准

- 功能场景明确，具备通用复用价值，不属于单个项目定制化需求

- 符合Skill标准结构规范，配置完整，文档齐全

- 通过安全扫描与合规校验，不存在安全漏洞与违规内容

- 经过测试验证，执行效果达到预期标准，容错能力达标

#### 5\.1\.2 评审流程

1. 提交方提交Skill入库申请，附完整资产包与测试报告

2. 信息中心技术委员会组织技术评审、安全评审、合规评审

3. 评审通过后分配唯一标识与版本号，纳入全局Skill池

4. 同步更新至底层`common_skill/`目录，全平台可用

### 5\.2 版本运营与迭代

1. 全局Skill由信息中心技术委员会统一维护，定期迭代优化

2. 版本更新发布前必须经过测试验证与灰度验证，确保兼容性

3. 重大版本更新提前公示，说明变更内容与影响范围

4. 建立版本兼容矩阵，明确各版本与DSH引擎的适配关系

### 5\.3 复用度量与效果分析

1. 统计维度：调用次数、复用项目数、执行成功率、平均耗时、节省工时估算

2. 定期输出Skill运营分析报告，识别高价值能力与待优化项

3. 建立复用激励机制，鼓励贡献优质Skill资产

4. 长期低调用、低价值的Skill启动下线评估

### 5\.4 安全与合规管理

1. 所有Skill入库前必须经过安全扫描，禁止包含恶意代码、敏感信息

2. Skill执行权限遵循最小权限原则，严格控制文件系统、系统命令访问范围

## 第六部分 自定义Skill开发规范

### 6\.1 开发全流程

1. **需求定义**：明确Skill功能目标、适用场景、输入输出、性能要求

2. **设计开发**：按照标准结构开发配置、Prompt、脚本与附件

3. **测试验证**：在测试环境完成功能测试、兼容性测试、安全测试

4. **评审入库**：提交评审，通过后纳入对应层级Skill库

### 6\.2 标准目录结构与模板

#### 6\.2\.1 标准目录

遵循全局统一的Skill目录结构，使用`_template/`标准模板初始化项目，禁止私自调整核心文件路径。

#### 6\.2\.2 配置文件编写规范

- `skill.yml`必须包含元数据、参数定义、输入输出、依赖项完整字段

- 参数必须设置默认值与校验规则，必填参数明确标识

- 版本号、所属领域、作者信息必须完整准确

#### 6\.2\.3 Prompt编写最佳实践

- 明确角色定位与任务目标，设定清晰的执行边界

- 嵌入对应研发规范要求，确保输出符合标准

- 定义结构化输出格式，便于后续解析与归档

- 考虑异常场景处理，提升容错能力

- 禁止包含诱导越权、绕过安全校验的内容

### 6\.3 开发约束要求

1. **安全红线**：禁止内置后门、禁止越权操作、禁止收集敏感数据、禁止执行未授权命令

2. **性能要求**：常规Skill执行耗时不超过30秒，大场景任务不超过5分钟，支持超时终止

3. **兼容性要求**：兼容当前主流DSH引擎版本，不依赖特定项目的私有配置

4. **可维护性**：代码与配置注释清晰，逻辑结构合理，便于后续迭代

### 6\.4 测试与校验

1. **功能测试**：覆盖正常场景、异常场景、边界场景，验证输入输出正确性

2. **合规校验**：通过`verify_env.sh`工具校验目录结构、配置格式、合规性

3. **性能测试**：验证并发场景下的稳定性与资源占用

4. **安全测试**：扫描安全漏洞，验证权限控制有效性

### 6\.5 发布与同步

1. 项目级自定义Skill由项目经理审批发布，同步至项目`skills/`目录

2. 领域级Skill由领域负责人审批，同步至对应领域配置

3. 全局Skill由信息中心技术委员会审批发布，全平台同步生效

4. 发布后自动触发增量同步，更新智能体加载的能力版本
